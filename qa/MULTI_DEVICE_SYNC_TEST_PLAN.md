# Voyager QA — Multi-Device Sync Test Plan (two dev profiles)

Written 2026-10-12. The QA audit (`qa/TEST_PLAN.md`, phases 1–27 and FV-1…FV-41) ran with **one** Voyager instance. Every cross-device case was skipped ("one PC") or simulated by writing whole-document snapshots into Firestore with `evalc.ps1`. Dev profiles (`DEV_PROFILE_HLD.md`, implemented 2026-10-12) now give two real devices on this PC. Each has its own SQLite database, outbox, Firestore SDK cache, sign-in and `deviceId`, and both talk to the same Firestore project.

This plan covers what that newly makes testable:
- every sync path with a **real second device** on the other end;
- the cases the audit skipped or simulated (§2 maps each one to a test here);
- the sync code the audit never drove from two sides (§3).

The audit's rules still apply (`TEST_PLAN.md` "RULES"): no app code changes, `voyager-qa-*` accounts only, `guard.ps1` before anything destructive, log bugs in `qa/BUGS.md` as found (**next ID: BUG-249**; next free account: **qa-071**), and finish with SESSION END on **both** instances.

## 1. Setup

### 1.1 Topology

| Instance | How | Role |
|---|---|---|
| **A** | dev profile `qa` (`-Profile qa`) | "Device A". Built from the working tree. |
| **B** | dev profile `qb` (`-Profile qb`) | "Device B". Same exe, run beside A. |
| Juno's install | the normal instance | **Never touched.** Neither profile shares anything writable with it. |

Use two profiles, not a profile plus `-Profile default`. The default instance means quitting, signing out and wiping Juno's install. Only MD-8.9 (floaters) needs the normal instance, because profiles have no global hotkeys; it is optional and needs Juno's go-ahead first.

### 1.2 Bring-up (per session)

1. **A:** `session_start.ps1 -Email voyager-qa-0NN@example.com [-SignUp] -Profile qa`. This rebuilds the debug exe, then launches A and signs it in.
2. **B:** don't run `session_start.ps1` for B: its `-Build` refuses while A's debug exe is running. Run its steps by hand instead:
   `reset.ps1 -Profile qb` → `launch.ps1 -Profile qb` (no `-Build`) → `login.ps1 -Profile qb -Email <same account>` → `guard.ps1 -Profile qb`.
3. Both must print `GUARD OK` for the **same** QA account (except MD-12's two-account cases).
4. Park both (`voy.ps1 -Profile qa do "park"`, the same for `qb`). Background mode posts input to one PID, so input can't land in the wrong instance.
5. **Every PowerShell call names its instance explicitly** (`-Profile qa` / `-Profile qb`). Don't rely on `$env:VOYAGER_QA_PROFILE` in a two-instance test. Never run a bare `stop.ps1`: it kills every `voyager.exe`, Juno's release included.
6. Record in the session log: `git log -1 --oneline`, `git status --short lib/`, both `deviceId`s (Dev page or `settings_table.device_id`), and both run-log names (`qa/logs/run-qa-*.exe.log`, `run-qb-*.exe.log`).
7. **Rebuilding mid-session:** `stop.ps1 -Profile qa` and `stop.ps1 -Profile qb` first. The build replaces the exe both run from.

### 1.3 Oracles

Each test says which of these proves it:

- **O1 Row diff A↔B.** Read-only SQLite on both databases (`%APPDATA%\Voyager\voyager-profile-{qa,qb}\voyager.sqlite?mode=ro`). **Harness to add (`qa/harness/dbdiff.py`):** compare every synced table row by row, by id, on `version`, `updated_at`, `deleted_at` and content columns. Ignore device-local state: `pending_uploads_table`, sync watermarks, `settings_table` device-local columns (PROGRESS.md "Device-local settings"), `sync_conflicts`, and per-device logs. Output: rows only on A, only on B, and differing.
- **O2 Firestore.** `fs_snapshot.sh <uid>` (read-only REST) before/after. It covers 38 of the 62 collections; extend its list for collections a test touches that it lacks (counter adjustments, ranking counts, cheat sheet, snippets, flagged words, device registrations, entity reminders, delivery states/logs).
- **O3 Outbox drained** on both: `pending_uploads_table` = 0 (queued and parked).
- **O4 In-app check.** Dev → "Check every collection against the cloud" on **both** reports safe (BUG-217 is fixed; any flag is a finding). The journal / to-do compare tiles report no mismatch.
- **O5 UI without a restart.** B's page shows the change **without** `stop`/`launch`: live sync has to refresh providers (FV-2's known gaps: custom quotes and historical journal entries).
- **O6 Clean logs.** No `EXCEPTION CAUGHT`, `Another exception`, `RenderFlex overflowed` or `LiveSyncController` errors in either run log. Each profile's `logs\voyager_errors.log` gains only APP START lines.
- **O7 Latency.** Time from A's save (A's `[sync] … upsert` line with Verbose sync on, or the step's timestamp) to B's row change (poll B's DB every 250 ms). **Harness to add (`qa/harness/wait_row.py <db> <sql> <timeout>`):** waits until a read-only query returns a match and prints the elapsed time.

Turn on **Dev → Verbose sync** on both instances for the whole run. It's device-local, so it has to be set on each.

### 1.4 What one PC still can't do (state these in results, don't work around them)

- **One clock, one timezone.** Clock skew and cross-timezone reminder cases stay unit-test only (FV-5). Simulate skew only through `evalc` writes with crafted stamps, and label it simulated.
- **One network.** The per-instance offline lever is **Dev → Force offline**. It disables Firestore's network, media storage, Geoapify and tiles, but **not sign-in or weather** (P26). A real network cut affects both instances at once and needs admin rights.
- **One AUMID.** Both instances post OS toasts as `Voyager.App`. Clicking a toast may activate either instance (DEV_PROFILE_HLD §10 Q2), and clicking toasts is MANUAL-ONLY anyway.
- **No global hotkeys or Start with Windows in profiles.** Floaters only on the normal instance (MD-8.9, optional).
- **Exactly-same-millisecond collisions** (`hardMetadataCollision`: same version **and** same `updatedAt`, different metadata) can't be produced by hand. MD-15.4 crafts one with `evalc`.
- **Time-based expiry** (7-day outbox park, 30-day tombstone purge, weekly full pull) can't be waited out. Age stamps in SQLite with the app stopped, as FV-4 did, and say so.
